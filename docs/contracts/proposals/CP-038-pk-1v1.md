**Status: OWNER REQUEST (2026-10-31, via the coordinator: «فعّل PK ثنائي ولا تنسَ التربل والدبل») with every
number an OWNER-CONFIRMABLE DEFAULT — built in D195 (contract v1.43-live, CONVENTIONS §10.58).** Builds on D71 / D73

(CP-020, D132 lucky gifts, D179 cherries). The owner's earlier PK notes stay in the coordinator's PK design (scratch).

## 1. Owner decisions

| Topic | Decision (owner) |
|-------|------------------|
| What | PK 1 v 1 between two live **video** hosts, for real (server-authoritative). |
| Starting | Invite a host live now (search + suggestions) or «مطابقة عشوائية»; invitations expire; a host can turn invitations off; a cooldown and rate limits. |
| Match | A battle, then a result / "punishment" phase with the win / lose animation; ending early is a forfeit; a host who disconnects or stays away loses; draws exist. |
| Media | Each room's viewers see both hosts side by side with the PK bar; each room keeps its own chat, gifts and seats; the hosts hear each other, viewers hear both, each host can mute the opponent. |
| Score | PK points = the coin value of each room's gifts during the battle × the active booster. **Multipliers affect only PK points** — never host earnings, cherries, live score, rankings, charm or levels. Lucky gifts count their coin value. |
| Boosters | Exactly four: «دبل» ×2, «دبل تيربو» ×3, «تربل» ×5, «تربل تيربو» ×10, each with its own gift. The other tools (Fog, Freeze, Shield, Extra time, MVP, Quick strike, Steal, Crit) are not in this phase. |
| Guests | Each host's guests as small glowing circles at the bottom of their box, at most 3. |
| Result | The existing win / lose SVGA, the top 3 supporters per side, a stored history, a W / L / D record on the profile; rewards non-monetary and later. |
| Safety | Server-authoritative, idempotent gift accounting, no PK with a blocked host, a moderator can end one (audited CLI). |

## 3. Media (design)

No new LiveKit room and no server-side forwarding: viewers and hosts of each room open a **second, subscribe-only,
hidden connection to the other room's media session** with a token from `createLivePkMediaToken` (identity
`pk:<matchId>:<identity>`). Each room keeps its own chat, gifts, seats and viewer list (the webhook never records
`pk:` identities as viewers), the other room's guests are visible too (PK guests), and the watchers are removed when
the match closes. Cost: one more LiveKit participant per viewer during a PK. Verified on a local `livekit-server`
1.9.1 with `@livekit/rtc-node` clients (`d195-pk-livekit-real.e2e-spec.ts`).
