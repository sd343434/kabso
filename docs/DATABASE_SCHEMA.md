# Kabso Live — Database Schema (Phase 1)

Source of truth: [`apps/api/prisma/schema.prisma`](../apps/api/prisma/schema.prisma) and the
migrations in `apps/api/prisma/migrations/`. PostgreSQL 16.

Conventions: snake_case tables/columns (`@@map`/`@map`), UUIDv7 primary keys generated by Prisma
(`@default(uuid(7))`, time-ordered), all timestamps `timestamptz(3)` (UTC, millisecond precision).
Secrets are never stored in plain form: passwords are Argon2id PHC strings; refresh and
verification secrets are stored as SHA-256 hex.

## Tables

### `users` (owner: users module)

| Column | Type | Notes |
| ------ | ---- | ----- |
| id | uuid PK | UUIDv7 |
| email | varchar(254) UNIQUE | normalized (trim + lowercase); CHECK `users_email_normalized` |
| email_verified_at | timestamptz null | |
| password_hash | varchar(255) | Argon2id (m=19 MiB, t=2, p=1); upgraded on login if params change |
| status | enum `user_status` | ACTIVE \| SUSPENDED \| DELETED (default ACTIVE) |
| role | enum `user_role` | USER \| ADMIN (default USER) |
| created_at / updated_at / deleted_at | timestamptz | |

### `user_profiles` (owner: users module) — 1:1 with users, `ON DELETE CASCADE`

| Column | Type | Notes |
| ------ | ---- | ----- |
| user_id | uuid PK, FK → users.id | |
| username | varchar(30) UNIQUE | lowercase; CHECK `user_profiles_username_format` = `^[a-z0-9](?:[a-z0-9._]{1,28}[a-z0-9])?$` |
| display_name | varchar(50) | |
| bio | varchar(300) null | |
| avatar_url | varchar(2048) null | |
| locale | varchar(8) | `ar` (default) \| `en`; CHECK `user_profiles_locale_valid` |
| created_at / updated_at | timestamptz | |

### `user_settings` (owner: users module) — 1:1, `ON DELETE CASCADE`

`user_id` PK/FK, `is_private boolean default false`, timestamps.

### `sessions` (owner: auth module) — N:1 users, `ON DELETE CASCADE`

| Column | Type | Notes |
| ------ | ---- | ----- |
| id | uuid PK | also the `sid` JWT claim and the prefix of the refresh token |
| user_id | uuid FK | |
| refresh_token_hash | char(64) | SHA-256 of the current secret |
| previous_refresh_token_hash | char(64) null | previous secret: presenting it is reuse → revoke (only this secret revokes) |
| rotation_counter | int | incremented on every rotation |
| device_name / platform / app_version | varchar | from the client's `device` object; platform CHECK `sessions_platform_valid` |
| ip / user_agent | varchar | at creation |
| created_at / last_used_at | timestamptz | `last_used_at` updated on login and refresh |
| expires_at | timestamptz | sliding: now + 30 d at each rotation, capped by absolute |
| absolute_expires_at | timestamptz | created_at + 180 d; CHECK `expires_at <= absolute_expires_at` |
| revoked_at / revoked_reason | timestamptz / varchar(32) | LOGOUT \| USER_REVOKED \| REFRESH_REUSE \| PASSWORD_RESET |

Indexes: `(user_id, created_at DESC)` (session list), `(expires_at)` (future cleanup job).
Refresh rotation is a compare-and-swap: `UPDATE … WHERE id = $1 AND refresh_token_hash = $old AND revoked_at IS NULL`.

### `verification_tokens` (owner: auth module) — N:1 users, `ON DELETE CASCADE`

`id`, `user_id`, `purpose` (enum EMAIL_VERIFY \| PASSWORD_RESET), `token_hash char(64) UNIQUE`,
`expires_at` (24 h / 1 h), `consumed_at` (single use; issuing a new token consumes outstanding
ones of the same purpose), `created_at`. Indexes: `(user_id, purpose)`, `(expires_at)`.

### `audit_logs` (append-only)

`id`, `actor_user_id` (FK → users, `ON DELETE SET NULL` so the trail survives deletion), `action`
(`auth.register`, `auth.login.success`, `auth.login.failure`, `auth.login.rate_limited`,
`auth.logout`, `auth.refresh.reuse`, `auth.refresh.invalid_secret`,
`auth.email.verified`, `auth.password.reset_requested`, `auth.password.reset`,
`auth.session.revoke`), `target_type`, `target_id`, `metadata jsonb` (never secrets or raw
identifiers), `ip`, `request_id`, `created_at`. Indexes: `(actor_user_id, created_at DESC)`,
`(action, created_at DESC)`, `(target_type, target_id)`.

## Lookup paths → indexes

| Lookup | Index |
| ------ | ----- |
| login / register / forgot by email | `users_email_key` |
| login / availability by username | `user_profiles_username_key` |
| session by id (guard, refresh) | `sessions_pkey` |
| sessions of a user, newest first | `sessions_user_id_created_at_idx` |
| token by hash | `verification_tokens_token_hash_key` |
| outstanding tokens of a user | `verification_tokens_user_id_purpose_idx` |
